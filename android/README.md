# Android build

This directory contains the SDL2 Android application shell and Gradle build for Ship of Harkinian. The native game is built by the repository's CMake project as `libmain.so`; the Java activity uses SDLActivity to start its `SDL_main` entry point.

## Requirements

Initialize the repository submodules first with `git submodule update --init --recursive`. Install the Android SDK components below, then set `ANDROID_SDK_ROOT` (or `ANDROID_HOME`) and make sure `java` is Java 17:

- Android SDK Platform 35 and Build Tools 35.x
- Android NDK `27.2.12479018`
- CMake `3.31.6`
- Gradle 8.9 is downloaded by the checked-in wrapper

The NDK build fetches the pinned SDL and audio-codec sources from GitHub. The default APK includes `arm64-v8a` and `armeabi-v7a`. Choose another ABI set with `-PandroidAbis=arm64-v8a,x86_64` (or a single ABI to reduce build time).

## Prepare the game archive

`soh.o2r` is generated by a **host** build; an Android NDK build cannot run the asset packer. From the repository root, build it once on Linux, macOS, or Windows:

```sh
cmake -S . -B build-host -DCMAKE_BUILD_TYPE=Release
cmake --build build-host --target GenerateSohOtr --parallel
```

The host build writes `soh.o2r` at the repository root. That archive already contains `soh/assets/custom` and the generated shader assets, so Android stages the archive plus `soh/assets/yml` into the APK; the activity copies them into the app's private files directory at first launch. The YAML tree is about 120 MB, so allow extra time and storage for the first install. The generated archive is ignored by Git and is not bundled in this source checkout.

The `generate-builds` GitHub Actions workflow runs `GenerateSohOtr` on a host runner, then passes that artifact to the Android job; CI does not depend on a checked-in archive. For local builds, you can point staging at existing host outputs with `-PsohOtrPath=/path/to/soh.o2r` and `-PsohYmlAssetsDir=/path/to/yml`.

## Build and install

From this directory:

```sh
./gradlew assembleDebug
./gradlew installDebug
```

Or install `app/build/outputs/apk/debug/app-debug.apk` with `adb install -r`. A release APK can be assembled with `./gradlew assembleRelease`; signing configuration is intentionally left to the packager.

## ROMs, storage, and controls

No ROM is included. On first run, use the in-game extractor's ROM picker to select a legally obtained Ocarina of Time ROM. Android's Storage Access Framework grants access to that one file; the app copies it into its app-private files directory so the extractor can find it on later launches, and does not request broad storage permissions. App-specific external files storage is used when available, with an internal-files fallback if Android cannot provide it; temporary extraction data is kept in the app-private cache.

The on-screen controls can be hidden with **T** and the menu can be opened with **M**. Android Back also toggles the in-game menu. A physical controller is supported through SDL2. The touch buttons follow the project's default keyboard mappings; the left analog area acts as the left stick.

## Notes

- The native build uses GLES 3.0 and the SDL2 Android activity/runtime.
- NDK linker alignment is configured for devices with 16 KB memory pages.
- The SDL2 Java support classes are copied from SDL 2.32.10. License notices for SDL2, SDL_net, the audio codecs, Dear ImGui, libultraship, and Prism are kept under `android/licenses` and packaged in the APK assets.
- Android SDK/NDK, Gradle, and Java are required to assemble or run the app. This repository checkout does not itself contain an APK.
